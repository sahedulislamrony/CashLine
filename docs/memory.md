## 2. Product guardrails carried over

- Cash received, unpaid invoices and expected income are shown separately; estimates show assumptions and never tell the user whether to buy.
- V1 does not collect payments, calculate tax, or claim legal invoice compliance in any jurisdiction.
- External wallet linking, bank ingestion, tax filing, payroll and double-entry bookkeeping are outside V1.
- Client, invoice, line-item and allocation data live only in the encrypted vault and in encrypted backups.

## 4. Verification status

Verified:

- Light/dark design-token contrast pairs were recomputed on 2026-10-13. The light `outlineStrong` token was corrected to `#728279`.
- `expo-sqlite` documents a `useSQLCipher` config-plugin option (needs a development build, not Expo Go).
- Android documents `allowBackup` / `dataExtractionRules` / `fullBackupContent` exclusions for cloud-backup and device-transfer.
- Expo documents Router native tabs as beta in recent SDKs (import path changed in newer docs). In SDK 57 the import is `expo-router/unstable-native-tabs`.
- Phase 0, on 2026-10-13 (macOS, Node 24): `pnpm check` passes (format, lint, typecheck, 88 Jest tests, 100% coverage of the code that exists); `expo prebuild` generates both native projects with the expected identifier and `allowBackup="false"`; `expo export` bundles the app for iOS and Android.
- 2026-10-14: all CI jobs pass on `main` (lint/test, audit, secret scan, iOS and Android development builds). The CI-built iOS development build was installed and launched on an iPhone 18 Pro simulator (iOS 27.0): all five tabs render and switch, and native tabs show the Liquid Glass tab bar without extra code.
- 2026-10-14: currency exponents were compared with Node's ICU 78 / CLDR 48 data. They agree except for 16 currencies where CLDR formats with 0 decimals but ISO 4217 defines 2 or 3 (AFN, ALL, COP, HUF, IDR, IQD, IRR, KPW, LAK, LBP, MGA, MMK, PKR, SOS, SYP, YER). The table follows ISO, so money formatting (plan task 1.3) must set the fraction digits from the table and not rely on `Intl` defaults. The ISO data came from the `datasets/currency-codes` mirror (revision 2026-02-01) because the SIX publication site was unreachable; compare against the SIX list before release.
- 2026-10-14: the SDK 57 type definitions of `expo-secure-store` 57.0.4, `expo-local-authentication` 57.0.3 and `expo-crypto` 57.0.4 (all MIT, no runtime dependencies beyond `invariant`) were read. They document: string values only (the adapter must base64-encode bytes); `requireAuthentication` bound to biometrics; `getItemAsync` resolving `null` both for a missing entry and for one invalidated by a biometric change; `WHEN_UNLOCKED_THIS_DEVICE_ONLY` and `WHEN_PASSCODE_SET_THIS_DEVICE_ONLY` accessibility on iOS; a config plugin with `configureAndroidBackup` and `faceIDPermission`; synchronous `Crypto.getRandomBytes`; `LocalAuthentication.getEnrolledLevelAsync`. The secure-store docs also state that simulators and emulators do not require biometric authentication when reading, so auth-bound behavior can only be tested on real devices.
- 2026-10-14: the key hierarchy was tested in Node against real libsodium (`libsodium-wrappers-sumo` 0.8.4, WebAssembly build of libsodium 1.0.22) through the same adapter the app uses. Checked: Argon2id output equals OpenSSL's (Node `crypto.argon2Sync`); XChaCha20-Poly1305 matches the IETF draft test vector; SHA-256 matches FIPS vectors; `crypto_kdf` equals keyed BLAKE2b with salt and personalization; the BIP39 word list has the official SHA-256 and all eight official 24-word vectors pass.
