# Contributing to Cashline

Thanks for helping. Cashline handles people's financial records, so correctness and privacy come before speed.

By taking part you agree to the [Code of Conduct](CODE_OF_CONDUCT.md). Security problems are reported privately: see [SECURITY.md](SECURITY.md).

## Before you start

1. Read [`docs/project-specifications.md`](docs/project-specifications.md), [`docs/architecture.md`](docs/architecture.md), [`docs/security.md`](docs/security.md) and [`docs/development.md`](docs/development.md). Read [`docs/design-system.md`](docs/design-system.md) before changing UI.
2. Check [`docs/memory.md`](docs/memory.md) for current decisions and open questions.
3. For anything larger than a small fix, open an issue first so the approach can be agreed. Features outside the V1 scope (spec §3) are unlikely to be merged.

## Setup

Requirements:

- Node.js 24 (`.nvmrc`) and pnpm 11 (`corepack enable` picks the pinned version)
- iOS: macOS with Xcode and CocoaPods
- Android: Android Studio with an SDK and JDK 17

```bash
pnpm install
pnpm ios       # build and run the development build on a simulator
pnpm android   # build and run the development build on an emulator or device
pnpm start     # start Metro for an already installed development build
```

To build without launching (the same commands CI runs):

```bash
pnpm build:ios       # simulator build → ios/build/Build/Products/Debug-iphonesimulator/Cashline.app
pnpm build:android   # debug APK → android/app/build/outputs/apk/debug/app-debug.apk
pnpm build           # both
```

Cashline does not run in Expo Go: encrypted storage needs native code, so all work uses development builds. The `ios/` and `android/` folders are generated by `expo prebuild` and are not committed; change native behavior through `app.json` and config plugins.

## Checks

```bash
pnpm check           # format check, lint, typecheck, unit tests
pnpm test:watch      # tests in watch mode
pnpm test:coverage   # tests with coverage (90% global threshold)
pnpm lint:fix        # apply lint fixes
pnpm format          # apply Prettier
pnpm test:e2e        # Maestro flows in .maestro/ against an installed build
```

CI runs the same checks, plus a dependency audit, a secret scan, CodeQL, and development builds for iOS and Android.

## Tests

- Unit and component tests use Jest and React Native Testing Library and sit next to the code as `*.test.ts(x)`.
- Use test-driven development for money, dates, invoices, allocation, the outlook, recurrence, encryption, migrations, backup and entitlements (`docs/development.md` §1 and §5): write the failing test first.
- End-to-end flows use [Maestro](https://maestro.dev) and live in `.maestro/`.
- Never use real financial data, recovery phrases or backup files in tests, fixtures, issues or screenshots.
- Do not say a test passed unless it ran, and say which platforms you verified on.

## Architecture rules

```text
Presentation → Application → Domain ← Data → Platform
```

Domain and application code is pure TypeScript. Native capabilities live behind interfaces in `src/platform/`. ESLint enforces the import boundaries (see [`src/README.md`](src/README.md)); do not disable those rules to make a change pass.

## Dependencies

Every new dependency needs the checks in `docs/security.md` §13 (maintenance, advisories, native permissions, transitive dependencies, Expo SDK compatibility), summarized in the pull request. Add Expo-managed packages with `pnpm exec expo install <package>` so versions match the SDK. Packages published less than three days ago are rejected by the install policy in `pnpm-workspace.yaml`.

## Commits and pull requests

- Use [Conventional Commits](https://www.conventionalcommits.org): `feat(money): add currency table`, `fix(ledger): …`, `test(…)`, `docs: …`, `chore: …`.
- Sign off every commit with `git commit -s`. The sign-off certifies the [Developer Certificate of Origin](https://developercertificate.org): you wrote the change or have the right to submit it under the project license. There is no CLA.
- Git hooks run lint-staged and commitlint locally; CI checks every commit in a pull request.
- Keep pull requests small and scoped to one change. Update the relevant doc, and `docs/memory.md` when a decision changes.
- Decisions that are hard to reverse get an ADR in [`docs/adr/`](docs/adr/README.md).
